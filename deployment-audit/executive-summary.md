## What the website actually is

Chiransh Foods is a bilingual brochure and order-enquiry site for a vegetarian Gujarati food business in Ahmedabad. Customers can read the menu in English or Gujarati, call, open WhatsApp, or send an enquiry form. There is no shopping cart, no online payment, and no staff login.

The public site is one Node.js program. It serves the pages and a small API from files in the project. The Python code in `backend/` is only for local development and tests. It is not what Render runs.

The live homepage, menu, contact page, Gujarati homepage, FAQ, and privacy page answered successfully on the evening of 28 October 2026. HTTP requests were redirected to HTTPS. Security headers on the live site match the Node program in this repository.

## What works

- The menu, about, gallery, contact, FAQ, privacy, terms, and refund pages exist in English and under `/gu` in Gujarati.
- Page titles, descriptions, canonical links, language alternates, and a sitemap are generated by the live Node server.
- The contact form checks the name, phone, email, and message length, and it ignores hidden spam fields.
- Images are mostly WebP. Fonts are stored with the site, not loaded from Google at view time.
- No API keys or passwords were found in the source code.

## What needs a decision before any move

1. **Order enquiries are saved in a file inside the application folder.** Hostinger replaces that folder on every new deploy. A redeploy can delete enquiries. Render’s disk type was not visible from here, so the current host may have the same risk. WhatsApp and phone orders are unaffected. The form must not be the only copy of an order until this is solved.
2. **Hostinger must be told to run `server.mjs`, not to publish the React build as a static site.** If it publishes only the static build, the menu API, the enquiry form, and the per-page search tags stop working.
3. **The site still tells Google that its address is the Render URL.** That is correct today. Change it only when the new domain is on HTTPS and you have approved the switch.
4. **Do not turn off the Render site** until the new copy has been tested on a temporary address.

## Recommended hosting

Use **Hostinger Web Hosting Unlimited** (the current name of the Business web plan) and deploy the repository as a **Node.js Web App** on **Node.js 22**.

Official Hostinger limits, updated 9 October 2026, say this plan includes Node.js. The cheaper Single and Premium plans are listed as **not** including Node.js websites, even though the India pricing page shows a Node.js badge on those plans. Do not buy Single or Premium for this project unless Hostinger support confirms Node.js in writing at checkout.

This site does not need a VPS. Python, PostgreSQL, WebSockets, and background workers are not part of the live site.

**Fallback:** buy the domain at Hostinger, leave the website on Render, and point DNS to Render. Choose this if a Hostinger test build cannot start `server.mjs`, or if you want the smallest possible change.

## What you can do in Hostinger hPanel

- Buy the domain, edit DNS, turn on the free SSL certificate, and add mailboxes.
- Connect the GitHub repository, choose Node 22, and set the start file to `server.mjs`.
- Read build logs and restart the Node app.

## What hPanel does not do for you

- It will not keep enquiry files across deploys unless the storage design is changed.
- It will not run the Python API, PostgreSQL, or a private background worker.
- It will not update the canonical URL in the code. That is a later, separate code change.
- A VPS would add Linux updates, a firewall, and a process manager. That work is unnecessary for the current site.

## Security in plain language

The live site already sends strict browser protections and redirects HTTP to HTTPS. The form is rate-limited. There is no admin password to steal because there is no admin area.

The sensitive item is the enquiry file: customer names and phone numbers in a JSON file, with no documented backup. Fix the storage plan before the form is your only order book.

## Critical checklist before a launch on a new address

- [ ] Buy Unlimited hosting, or confirm Node.js another way. Do not rely on Single or Premium.
- [ ] Deploy to a temporary Hostinger address. Confirm `server.mjs` is running.
- [ ] Open `/`, `/menu`, `/contact`, and `/gu` and confirm titles are specific, not the generic built file only.
- [ ] Send a test enquiry and prove you can still read it after a restart and after a second deploy.

- [ ] Leave Render online. Change DNS only after you approve it.
- [ ] After HTTPS works on the new name, update the canonical address and resubmit the sitemap.
